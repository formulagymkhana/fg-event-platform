## 2. 数値を読むときの前提

この画面は**判断材料を出すだけ**で、評価や推奨はしない方針（2026-08-26 ユーザー確定）。
注釈は「何を含み何を含まないか」に限る。以下は取り違えやすい点。

- **選手は一律加算。** 来場予定日を持たないため全開催日に加算する。したがって選手側の
  「アクションなし」は欠席ではなく「来場したが何も操作しなかった」と読む。
- **弁当は日別、記録なしは通算。** 「弁当×アクション」はその日に記録があるかを見るが、
  「全開催日を通じて記録が無い学生」はどの日にも記録が無い人だけ。片方の日しか来ていない
  学生は前者に入り後者には入らないので、必ず前者の方が大きい数になる。
- **当日登録者は登録と同時に記録が付く。** 登録した日は必ずアクションありになる。
  弁当のクロス集計の母集団を「事前登録した選手以外」に限っているのはこのため
  （当日登録者を入れると「弁当なし×アクションあり」が当日登録者で埋まる）。
- **企業別QRは実人数。** `companyId + studentId` で重複排除している。行数を数えてはいけない
  （`actionSaveViewLog_` の重複抑制は `company_auto` のみで、`manual_email` には無く、
  ロックも取らないため重複行が残りうる）。同じ理由で日別には割らない。
- **来場したが無操作の人と、来ていない人は区別できない。** 機器不具合で記録が残らなかった
  場合も「アクションなし」に入る。

## 3. 保守上の注意

- **共通CSS(`js/style.css`)を変更しない。** 学生画面全体へ影響する。開催報告の調整は
  `app/report.html` 内で完結させる。admin.html は `--navy`/`--gray`/`--border` の
  ローカル別名を定義しているが実体は `--fg-*` なので、report では実体名を直接使う。
- **画面でカードを入れ子にしない。** KPI(`.stat-card`)は `.section` の外に直接置く
  （admin.html のダッシュボードと同じ並べ方）。
- **`adminGetAttendanceReport` は読み取り専用を維持する。** 表示変更を理由に
  シート書き込みやデータ補正を追加しない。
- **ログシートは1回だけ読む。** `readLog_` で正規化配列にしてから各集計で共有している。
  集計を追加するときも読み直さない（以前 STAMP_LOG / VIEW_LOG を各3回読んでいた）。
- **シート・列の欠落は握りつぶさない。** `warnings` に積んで画面に出す。
  黙って0件にすると「記録が無い」のか「集計できていない」のか区別できなくなる。
- **`js/report.js` 更新時は `app/report.html` のキャッシュバスターも更新する。**
- 印刷は配布用の帳票として扱う。並び順と表はそのままに、影と面の背景だけ落とす。
  折りたたみは `@media print` で強制展開するので、JS側で開閉状態を触らない。

## 4. 検証時の重点項目

- 長いイベント名で固定ヘッダーとアクション行が崩れないこと
- ブース数・大学数が多い場合の横スクロールと、375px幅
- A4印刷プレビュー（折りたたみが開き、影が消えていること）
- **企業別QRの合計が、活動記録のQR実人数と整合すること**（実人数同士なので一致するはず）
- 「学生来場（延べ）」が日別合計と一致し、登録選手数と選手延べ数を混同していないこと
- CSVを Excel で開いて文字化けしないこと（BOM付きUTF-8。`downloadCsv_` が付与）
