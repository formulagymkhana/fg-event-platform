# GAS コード同期を clasp へ移行する手順（2026-08-17 作成）

GAS のコードを `docs/gas-patches/*.final.txt` の手動コピペで反映する運用を、
Google 公式 CLI の `clasp` による同期へ切り替えるための手順書。

**この文書は「移行前」の状態で書かれている。移行が完了したら §6 に従って
CLAUDE.md を書き換え、この文書は履歴として残す（削除しない）。**

---

## 0. 最重要：正を2つ作らない

移行でいちばん危険なのは、`docs/gas-patches/*.final.txt` と `gas/` の
**両方が「正」に見える期間を作ってしまうこと**。どちらを直せばよいか分からなくなり、
片方だけ直した状態で push すると、もう片方の修正が静かに巻き戻る。

そのため本手順では次を徹底する。

| フェーズ | 正（唯一の真実） | `gas/` の状態 |
|---|---|---|
| 移行前（現在） | `docs/gas-patches/*.final.txt` | **存在しない** |
| 検証中（§3） | `docs/gas-patches/*.final.txt` | `gas-verify/` に隔離（git管理外） |
| 移行後（§5以降） | `gas/`（clasp管理） | リポジトリで追跡 |

検証用の clone は `gas-verify/` に置く。ここは `.gitignore` 済みなので、
差分ゼロを確認するまでリポジトリ内に二重ソースは生まれない。

**`gas/` を作るのは §5 の切り替え時だけ。それまで作らない。**

---

## 1. 前提と制約

- このリポジトリには `package.json` も `node_modules` も無い（CLAUDE.md §1）。
  clasp は**グローバル導入または `npx` 実行**とし、リポジトリに npm 依存を持ち込まない。
- clasp の認証は対話的な OAuth。Claude Code のセッションからは実行できないため、
  §2〜§3 は Daiki さんの手元で実行する。
- 稼働中イベントの期間中は実施しない（再デプロイは数秒の断を伴う。CLAUDE.md §2）。

---

## 2. 導入

```bash
npm install -g @google/clasp
```

権限エラーが出る場合は、npm のグローバル install 先をホーム配下に変更するか、
以降のコマンドを `npx @google/clasp ...` に読み替える。

```bash
clasp login
```

**対象プロジェクトの所有者アカウントでログインすること。**
別アカウントだと後続の clone が失敗するか、別プロジェクトを掴む。

---

## 3. 検証（ここが本番。push はまだしない）

### 3-1. 使い捨てディレクトリへ clone

```bash
mkdir -p gas-verify && cd gas-verify && clasp clone <スクリプトID>
```

`gas-verify/` は `.gitignore` 済み。ここに落ちたものはコミットされない。

### 3-2. 現行の `.final.txt` と差分を取る

clasp はファイルをローカルへ落とす際、既定で拡張子が `.js` になることがある
（`.clasp.json` の `fileExtension` 設定に依存する）。**実際に落ちたファイル名を
確認してからコマンドを組むこと。** 以下は `.gs` で落ちた場合の例。

```bash
diff gas-verify/api.gs docs/gas-patches/api.gs.final.txt
```

```bash
diff gas-verify/admin.gs docs/gas-patches/admin.gs.final.txt
```

### 3-3. 差分の読み方（ここが移行の可否を決める）

- **差分ゼロ** … 想定どおり。`.final.txt` は実体と一致していた。§4 へ進む。
- **差分あり** … **これは事故ではなく発見。** CLAUDE.md §5 が
  「GAS側とリポジトリの乖離を機械的に検出する手段がない」と書いている、その乖離が
  実在したということ。**この時点では絶対に push しない。**
  どちらが正しいかを1件ずつ判断し、`.final.txt` 側へ取り込んでから §4 へ進む。
  判断が必要な差分が出たら、内容を Claude Code に渡せば分析できる。

### 3-4. `appsscript.json` の確認

clone すると `appsscript.json`（マニフェスト）も落ちてくる。ここには
タイムゾーン・OAuth スコープ・Web アプリの実行ユーザーやアクセス権が含まれる。

**このファイルは push 対象に含まれ、現在のデプロイ設定を上書きしうる。**
中身が現在の設定と一致しているか、切り替え前に必ず目視する。

---

## 4. 初回 push の前に

差分ゼロ（または `.final.txt` へ取り込み済み）になって初めて push できる。

**`clasp push` は GAS エディタの中身をローカルの内容で丸ごと上書きする。**
差分を確認せずに push すると、エディタ上にしか無い変更が消え、しかも気づけない。

初回だけは、実行前に GAS エディタでコードをどこかへコピーして退避しておくと安全。

---

## 5. 切り替え

1. `gas/` をリポジトリに作り、検証済みのコードと `appsscript.json` を配置する
2. `.clasp.json` の `rootDir` を `gas/` に向ける（`.clasp.json` 自体はコミットしない）
3. **`docs/gas-patches/*.final.txt` を削除する**（正を1つにする。履歴は git に残る）
4. CLAUDE.md を §6 のとおり書き換える
5. `docs/CHANGELOG.md` に移行を記録する

3 と 4 は**同じコミットで行う**。片方だけ入ると、正が2つある期間ができる。

---

## 6. 移行後に書き換える CLAUDE.md（草案）

### §2 から削除する項目

> - **`docs/gas-patches/*.final.txt` を変更したら「GAS 再デプロイ必須」と明示的にユーザーへ伝える。**
> - **`docs/gas-patches/*.final.txt` を変更するPRは、常に1つずつ完結させる**

前者は `gas/` の変更に読み替える。後者は clasp 導入後も**維持すべき**。
push とデプロイが分離している以上、「複数のGAS修正PRを未マージのまま並行して抱えない」
という制約は変わらない。

### §3 の全面書き換え

「リポジトリに `.gs` が含まれていない」という前提が消える。
`gas/` が実体と同期していること、同期手段が clasp であることを書く。

### §5 の技術的負債から削除できる項目

> - **GAS 側とリポジトリの乖離を機械的に検出する手段がない。**

`clasp pull` 後に `git diff` を取れば機械的に検出できるようになる。
**これが今回の移行の最大の目的。**

---

## 7. デプロイの自動化（要検証）

`clasp push` は GAS エディタ上のファイルを書き換えるだけで、
**既にデプロイ済みの Web アプリ URL には反映されない。**

既存のデプロイIDを指定すれば、URL を維持したままバージョンを更新できるはず。

```bash
clasp deploy -i <デプロイID> -d "説明"
```

- **`-i` を省くと新規デプロイになり、API URL が変わる。**
  URL が変わると `js/config.js` の `API_BASE_URL` を書き換えるまで全機能が停止する
  （USER_MANUAL.txt にも同じ警告がある）。
- 上記コマンドの挙動は**未検証**。clasp のバージョンによって差があるため、
  最初に試すときは実行後に必ず `js/config.js` の `API_BASE_URL` へアクセスして
  疎通を確認すること。

これが機能すれば、CLAUDE.md §1「最終的な運用形態」が挙げる開発者依存2件のうち、
**GAS の手動再デプロイが解消**する（キャッシュバスターの更新は clasp と無関係なので残る）。

---

## 8. 既知のつまずき（実例）

1. **`clasp push` だけでは公開中の Web アプリは更新されない**（§7）。
2. **デプロイ設定（実行ユーザー等）を変更すると、バージョン選択が古いものに戻ることがある。**
   その状態で保存すると、直前に push したファイルが「見つかりません」というエラーになる。
   設定変更時は必ずバージョンが「新バージョン」になっているか確認する。
3. **新しいサービスを使い始めると、既存の OAuth 認可にスコープが含まれず再認可が必要になる。**
   Web アプリ URL を直接開き直して認可し直す。

---

## 9. やめる場合（ロールバック）

§5 の切り替え前なら、`gas-verify/` を削除するだけで元に戻る。リポジトリは無変更。

切り替え後にやめる場合は、`gas/` から `docs/gas-patches/*.final.txt` を復元し、
CLAUDE.md を戻す。git 履歴から復元できるので情報は失われない。
