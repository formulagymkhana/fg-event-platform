## STEP 3: 整理案

### 3-1. ディレクトリ構造

**現状の構造は変更しない。**
`app/` + `js/` のフラット構成はページ数（12）に対して適切で、
ビルド無し前提では `js/` を細分化すると HTML 側の `<script>` パス修正が
全ページに波及して割に合わない。変更は以下 2 点のみ。

- `docs/screenshots/` → `.gitignore` に追加（`take-screenshots.js` で再生成可能な生成物のため）
- `docs/USER_MANUAL.md` の削除をコミット

### 3-2. ファイル整理の方針

| 対象 | 対応 | 理由 |
|---|---|---|
| `CLAUDE.md`（新規） | 作成 | Claude Code が自動読込する恒久ルールの置き場。CLAUDE_TASKS.md からルール部分を抽出 |
| `CLAUDE_TASKS.md` | ルール部分を CLAUDE.md へ移動し、履歴のみ残す or `docs/` へ移動 | 役割の混在を解消 |
| `README.md` | ページ表・ドキュメント一覧を実態に合わせて更新 | 3 ページ欠落の解消 |
| `docs/CHANGELOG.md` | 運用を「コミット毎」→「機能単位・GAS再デプロイ要否の記録」に緩和し、07-24 以降を 1 エントリで補完 | 72 件を遡って書くのは非現実的。git log と役割が重複しているため、CHANGELOG の価値は「GAS再デプロイ要否」の記録に絞る |
| `docs/NOTES.md` | 解決済み項目に「解決済み（日付）」を追記 | 削除ではなく判断の経緯を残す |
| `docs/HANDOFF_2026-07-24.md` | P0 を「対応済み」に更新。以後は追記せず、次回引き継ぎ時に新ファイル | 日付付きスナップショットとして正しい形 |
| `docs/screenshots/` | `.gitignore` へ | 生成物 |

### 3-3. `CLAUDE.md` に書く内容（案）

CLAUDE_TASKS.md から抽出＋今回判明した実態を反映した骨子。

**プロジェクト概要**（3行）
静的フロント（GitHub Pages）+ GAS バックエンド、ビルド無し。

**絶対に守ること**

- JS / CSS を変更したら、参照する全 HTML のキャッシュバスター `?v=` を必ず更新する
- `docs/gas-patches/*.final.txt` を変更したら「**GAS 再デプロイ必須**」と明示的にユーザーへ伝える（自動反映されない）
- `.claude/settings.local.json` は変更しない
- 稼働中イベント（現 `2026_rd2`）に影響する変更は、影響範囲を先に申告する

**設計上の確定事項（巻き戻し禁止）**

- 当日受付コードは撤廃済み
- イベント判定は日付駆動。状態は `公開中 / 公開停止` の 2 値のみ
- 出場校エントリーは学校名で重複判定・上書き型
- 書類URLは config + HTMLハードコードの二段フォールバック
- エントリー/受付リストは **CSV 出力のみ**が正式
- 走行順は 男子A → 女子A → 男子B → 女子B → 男子C（C まで）

**コミット規約**

`feat:` `fix:` `docs:` `style:` `revert:` プレフィクス、日本語本文。

**ドキュメントの読み方**

「実装が正、ドキュメントは参考」。
優先順位: コード > `USER_MANUAL.txt` > `HANDOFF` > `README` > `NOTES` / `CHANGELOG`

### 3-4. 命名規則（現状追認）

すでに一貫しているため、明文化するだけ。

- ページ: `app/<name>.html` ↔ `js/<name>.js` の 1 対 1 対応。ケバブケース（`register-school`）
- GAS 内部関数: `action<Name>_` / ヘルパーは末尾 `_`
- config キー: キャメルケース（`schoolEntryDeadline`）。
  **既存キーの改名は禁止**（CONFIG シートのマイグレーションが発生するため）
- キャッシュバスター: `?v=YYYYMMDD<a-z>`（同日複数回は英字を進める）
